# ADC Monitor (Rust + egui)

Desktop-приложение для мониторинга 10 каналов АЦП по последовательному порту. GUI написан на `eframe/egui`, графики — на `egui_plot`, последовательный порт — через `serialport`.

## Возможности

- 10 графиков, каждый занимает отдельную строку и растягивается по ширине доступной области.
- Справа от каждого графика отображается последнее принятое значение.
- Каждый канал можно включать и выключать. При подключении программа синхронизирует состояния каналов командами `ON_CHANNEL_XX` / `OFF_CHANNEL_XX`.
- Масштабирование колёсиком мыши, перемещение графика перетаскиванием правой кнопкой, сброс масштаба двойным щелчком.
- При наведении появляется вертикальная линия и подсказка со временем и ближайшим по времени значением.
- История каждого канала ограничена 5000 точками.
- Опрос выполняется в отдельном потоке, GUI не блокируется ожиданием платы.
- **Панель отладки serial-порта** показывает последние 512 реально принятых байтов в HEX и ASCII, а журнал — все отправленные команды `TX`, распознанные строки/кадры `RX`, значения float, частичные кадры и тайм-ауты. Журнал ограничен 1500 строками; RX и журнал можно очищать раздельно.
- Если команда настройки не получила `OK` до тайм-аута, приложение сохраняет запрошенное состояние канала для диагностики и всё равно пробует опрашивать его через `GET_ADC_XX`. Если плата явно ответила `Error command`, такой канал не включается.
- При подключении входной буфер serial-порта не очищается, и после тайм-аутов входные байты не сбрасываются автоматически: поздние ответы остаются доступными для отладки.

## Формат протокола

Настройки последовательного порта по умолчанию: **115200 бод, 8N1**, без аппаратного управления потоком. Скорость можно выбрать в интерфейсе.

Команды заканчиваются байтом `LF` (`\n`):

- `GET_ADC_01` … `GET_ADC_10` — запросить значение канала.
- `ON_CHANNEL_01` … `ON_CHANNEL_10` — включить мониторинг канала.
- `OFF_CHANNEL_01` … `OFF_CHANNEL_10` — выключить мониторинг канала.

Для команд включения/выключения программа ожидает текстовый ответ `OK\n` или `Error command\n`.

Ответ `GET_ADC_XX` трактуется как **4 байта IEEE-754 `f32` в little-endian, после которых идёт LF (`0x0A`)**. Поддерживается также завершающая последовательность CRLF. Порядок байтов в исходном ТЗ явно не определён; если прошивка платы выдаёт big-endian, замените `f32::from_le_bytes(bytes)` в `src/main.rs` на `f32::from_be_bytes(bytes)`.

> Важно: приложение предполагает, что на каждый `GET_ADC_XX` плата возвращает ровно один кадр из 4 байтов плюс перевод строки, без дополнительного текстового префикса/эхо команды.

## Как пользоваться отладкой

1. Откройте панель «Отладка последовательного порта» в верхней части окна (по умолчанию она раскрыта).
2. Нажмите «Подключить».
3. В журнале ищите `TX`: это команды, которые приложение отправляет плате. Команды отображаются и как текст с `\n`, и как HEX-байты.
4. Принятые байты появляются в поле RX даже в случае, если ответ неполный и позже наступил тайм-аут. Для текстового ACK появится запись `RX строка`, для АЦП — `RX ADC кадр` и затем декодированное число.
5. Если журнал показывает TX и тайм-аут, но RX пуст, приложение не получило ни одного байта. Проверьте порт, baud rate, GND, TX↔RX, уровень логики и то, что прошивка отвечает именно на эти команды.
6. Если RX показывает байты, но появляются сообщения о неправильном кадре, сравните HEX с фактическим протоколом платы. Это помогает определить порядок байтов и окончание кадра.

## Сборка и запуск

Требуется установленный Rust toolchain (`rustc`, `cargo`). Из каталога проекта:

```bash
cargo run --release
```

После сборки исполняемый файл можно запустить из `target/release/adc_monitor`.

### Linux

Для системных библиотек `eframe` и `serialport` на Debian/Ubuntu:

```bash
sudo apt install build-essential pkg-config libudev-dev libxcb-render0-dev libxcb-shape0-dev libxcb-xfixes0-dev libxkbcommon-dev libssl-dev
```

Для доступа к `/dev/ttyUSB*` или `/dev/ttyACM*` добавьте пользователя в соответствующую группу (часто `uucp` или `dialout`) и повторно войдите в систему.

### Windows

Откройте проект в терминале с установленным Rust и выполните `cargo run --release`. В поле порта укажите, например, `COM3`.
